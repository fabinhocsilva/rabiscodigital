# Rabisco Digital

A live classroom whiteboard: Node/Express/Socket.IO backend + Flutter Web client.

## Layout

```
server.js              — realtime backend (unchanged from the original Slate server)
package.json           — backend dependencies
public/                — built Flutter web app (auto-generated by CI, don't edit by hand)
rabisco_digital/        — Flutter app source (this is what you actually edit)
.github/workflows/      — CI: builds Flutter web and commits it into public/ on every push
```

## First-time setup

1. Push this repo to GitHub as-is.
2. On the first push, the GitHub Actions workflow (`.github/workflows/build-and-deploy.yml`)
   will run automatically: it builds `rabisco_digital/` with `flutter build web` and commits
   the result into `public/`. Expect a second, auto-generated commit right after your push.
3. Deploy on Render (or similar):
   - Build command: `npm install`
   - Start command: `npm start`
4. Render will redeploy on every push to `main`, including the CI's auto-commit.

## Day-to-day workflow

Edit files under `rabisco_digital/lib/`, then:
```
git add .
git commit -m "your change"
git push
```
GitHub builds it and updates `public/` for you — no manual `flutter build web` needed.

## Local development

```
npm install
npm start                 # starts server.js on http://localhost:3001

cd rabisco_digital
flutter pub get
flutter run -d chrome      # will ask for the server address — enter http://localhost:3001
```

## Notes

- No database — classrooms/accounts live in server memory. Restarting the server (or a
  Render redeploy without persistence configured) clears them.
- Free Render tiers sleep after inactivity; the first request after idle time can take
  10–30 seconds.
